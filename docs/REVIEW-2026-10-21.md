# Sample review — 21 October 2026

Review of the eight created template labs before they are used to compose complete homepages:

`homepage-hero` · `homepage-delivery` · `homepage-financial-clarity` · `homepage-why-nestlancer` ·
`homepage-selected-work` · `homepage-closing-cta` · `homepage-header` · `homepage-footer`

**Method.** Every HTML file was read; locked copy was diffed against
[`HOMEPAGE-SCREENSHOT-RESEARCH.md`](HOMEPAGE-SCREENSHOT-RESEARCH.md) and the numbered section prompts;
structure, ids, link targets, ARIA wiring and inline scripts were machine-checked; the accent/text
token pairs were measured for WCAG AA. Result after fixes:
`python3 tools/audit-samples.py` → **PASS** on all 46 files.

**Not verified.** No browser engine is available in this environment (no Chromium/Chrome/Firefox, and
browser downloads are blocked), so there are **no rendered screenshots** in this pass. Layout at
360 / 390 / 768 / 1024 / 1440 px was reasoned from the CSS (breakpoints, grid tracks, `clamp()`,
`min()`/`max-width`, `overflow`), not observed. Open the lab hub and spot-check visually before
composing.

## Second pass — composability and polish

Everything below came out of the same review, one level deeper: what breaks when these files are
combined into a page, or handed to a client.

| Area | Problem | Fix |
|---|---|---|
| Theme sync | Footer samples read `?theme=` and the OS only — a visitor who toggled the header stayed dark in the footer, and vice versa. | Boot now consults `nl-theme` between the query string and the OS, matching every other lab (8 files). |
| CTA destinations | **Start a project** pointed at `/proto/apps/landing/register/index.html` in the hero and closing CTA, but at `/contact` in the header and footer — one label, two destinations. | Unified on the locked prototype route (14 files, 18 links). `/contact` remains the nav link, not the CTA. |
| Touch targets | Floating theme buttons were 40 × 40 px on 21 pages; footer column links were 22 px tall. | 44 × 44 fabs, 40–44 px footer links (`P05` legal + nav already 44). |
| Selected-work gallery | Heading levels jumped `h1 → h3`; card titles were styled on `.copy h3`. | Card titles are `h2`, selector retuned; audit now fails on heading jumps. |
| Split viewer chrome | Window-chrome text was 8 px (`CONCEPT` badge) and 9.5 px (slug). | 9.5 / 10 px — the badge is real information, not decoration. |
| Broadsheet table | At 360 px the four-column statement summed to ~310 px of unbreakable content in a 312 px column — a horizontal scroll waiting to happen. | Under 520 px the redundant STAGE column is dropped (the same word sits under each item name), paddings and numerals tighten. No figure or label is lost. |
| Work imagery | Eight concepts had no intrinsic `width`/`height`, so cards shifted before the JPEGs landed. | Real dimensions from the files, `loading="lazy"` + `decoding="async"`; the pinned S10 preview stays eager. |
| Manifests | `sample.json` `source` pointed at `chrome-lab/approved/…`, a path this repo never had. | Points at the real sample file; audit validates JSON, `id` ↔ folder, and `name`. |
| Token drift | `homepage-prompt.md` still declared the old `--teal:#24877f`, so a future composer would reintroduce the contrast failure. | Master prompt carries `#1f7a72` plus the measured ratios. |
| Why-nestlancer toggle | W04/W05 were the only two samples whose theme button painted a text glyph (`☾` / `☀`) instead of the shared sun/moon SVG — inconsistent weight, and the sun renders as colour emoji on some platforms. | Both use the same inline SVG pair and CSS swap as the other 21 samples; the old `textContent` swap is gone. |
| Docs | Header/footer chrome had no pointer from the section-prompt README. | That README now names both chrome labs and their defaults. |

## Deliberately left as-is

* **`Tour the product` → `#how-it-works`** in the hero samples is a cross-section anchor. It is required
  by `01-hero.md` and resolves once the delivery section is composed beneath the hero (both `D*` samples
  keep `id="how-it-works"`).
* **Section-only scope.** No sample contains a header, footer or neighbouring section, so they must not
  be shipped as pages on their own; that is what `homepage-compositor-prompt.md` is for.
* **W04's “light” theme is intentionally a deep-teal canvas.** Both themes were checked for readable
  contrast; the light theme is not white by design.
* Illustrative previews (Project Hub, 68 %, ₹ figures, orbit diagrams) stay clearly labelled — they were
  never live data.

## Re-running the checks

```bash
cd ui-designing-homepage
python3 tools/audit-samples.py     # 46 files: structure, links, ARIA basics, copy locks, contrast, JS syntax
python3 -m http.server 8124        # then open http://127.0.0.1:8124/
```

`tools/audit-samples.py` is dependency-free; if `node` is present it also syntax-checks every inline
script. It is a regression net, not a substitute for looking at the page.
